# 显卡设备枚举排查经验

## 目标

显卡枚举接口需要返回物理 NVIDIA RTX 显卡：

- 一张物理卡只记录一次；
- 两张同型号物理卡应记录两次；
- 向日葵、ToDesk 等虚拟显示驱动不能计入物理 GPU 数量。

## 现象与根因

最初通过 `IDXGIFactory::EnumAdapters` 枚举 DXGI Adapter。在一张 RTX 3060 的电脑上，函数返回了三条相同的显卡名称，且三条 `AdapterLuid` 不同。

系统 Display 设备树中实际存在：

```text
ROOT\DISPLAY\0000                                  OrayIddDriver Device
ROOT\DISPLAY\0001                                  Todesk Virtual Display Adapter
PCI\VEN_10DE&DEV_2504&SUBSYS_88161043&REV_A1\...    NVIDIA GeForce RTX 3060
```

DXGI 枚举的是当前可用的图形适配器对象，而不是“物理 PCI 显卡清单”。远程控制软件安装的虚拟显示驱动会参与该枚举；在该环境中，它们还复用了 NVIDIA 的适配器描述，因此只按名称或 DXGI 数据无法可靠统计物理显卡。

## 字段判定边界

| 字段 | 用途 | 能否作为物理卡去重键 |
| --- | --- | --- |
| `Description` | 驱动提供的显示名称 | 不能；同名双卡、虚拟适配器都可能相同 |
| `VendorId + DeviceId` | PCI 厂商和 GPU 芯片型号 | 不能；两张相同型号卡必然相同 |
| `SubSysId + Revision + DedicatedVideoMemory` | 板卡/资源描述 | 不能保证唯一；相同品牌、型号、显存的双卡仍可能相同 |
| `AdapterLuid` | 当前 DXGI Adapter 对象标识 | 不能作为物理卡标识；虚拟显示驱动可对应不同 LUID |
| 完整 `PCI` Device Instance ID | Windows PnP 设备实例 | 可以；一张实体 PCI 显卡对应一个实例，两张实体卡实例不同 |

结论：`VendorId` 与 `DeviceId` 可以用于识别型号，但不能用于区分同型号实体卡；物理卡唯一性必须使用 PnP Device Instance ID。

## 当前实现

`GetGpuType` 可使用 SetupAPI 实现：

1. `SetupDiGetClassDevsW(&GUID_DEVCLASS_DISPLAY, ..., DIGCF_PRESENT)` 获取当前存在的 Display 设备；
2. 用 `SetupDiEnumDeviceInfo` 遍历设备；
3. 用 `SetupDiGetDeviceInstanceIdW` 读取完整设备实例 ID；
4. 仅保留以 `PCI\` 开头的实例，排除 `ROOT\DISPLAY\...` 虚拟显示设备；
5. 以完整实例 ID 去重；
6. 使用 `SPDRP_FRIENDLYNAME` 获取名称，失败时回退到 `SPDRP_DEVICEDESC`；
7. 保持原有 `RTX` 名称筛选和空白字符移除规则；
8. 最后调用 `SetupDiDestroyDeviceInfoList` 释放设备集合。

该方案在上述电脑上仅返回 `NVIDIAGeForceRTX3060` 一条；若安装两张 RTX 3060，则两个 PCI 实例 ID 不同，结果保留两条。

## 自动验证方法

可编写独立的 GPU 枚举回归测试：

1. 从应用运行目录动态加载目标 DLL；
2. `resolve("GetGpuType")` 后调用导出函数；
3. 用 `QProcess` 执行 `nvidia-smi -L`；
4. 只解析 `GPU <index>:` 行；
5. 两边名称都移除空白字符后排序，逐项比较数量和型号。

手工执行命令：

```powershell
nvidia-smi -L
```

示例输出：

```text
GPU 0: NVIDIA GeForce RTX 3060 (UUID: GPU-...)
```

运行时只执行该 GPU 校验用例即可，例如：

```text
--gtest_filter=GpuInfo.MatchesNvidiaSmi
```

`nvidia-smi` 不存在、启动失败、超时、退出失败或解析不到 GPU 行均应使该测试失败，因为该测试专门校验 NVIDIA 设备枚举一致性。
