# 差分筛选 HALCON 自动并行化耗时问题记录

## 背景

在 `BaseTool/multiplyjudgement.cpp` 的 `analysisDefectNew` 差分筛选流程中，分块模式会对每个缺陷分块做二次相位校正。现场部署机出现 `偏移计算` 耗时明显高于开发机的问题。

相关代码路径：

- `BaseTool/multiplyjudgement.cpp`
  - 差分筛选分块循环
  - 每块裁剪当前图/模板图
  - 调用 `phaseCorrelate`
- `BaseTool/basetool.cpp`
  - `BaseHTool::phaseCorrelate`
  - 内部使用 HALCON `RftGeneric`、`PhaseCorrelationFft`、`LocalMaxSubPix`
- `BaseTool/basetool.cpp`
  - `BaseHTool::BaseHTool`
  - HALCON 系统参数设置

## 现象

部署机上单个分块的 `phaseCorrelate` 耗时达到 16ms 级，导致 14 个分块累计耗时过高。

部署机关键日志：

```text
差分筛选分块13/14偏移计算-phaseCorrelate-RftGeneric1:5.1718
差分筛选分块13/14偏移计算-phaseCorrelate-RftGeneric2:5.5047
差分筛选分块13/14偏移计算-phaseCorrelate-互功率谱+反变换:4.7884
差分筛选分块13/14偏移计算-phaseCorrelate总:16.5327
差分筛选分块13/14偏移计算:17.3886
```

开发机同一类日志：

```text
差分筛选分块14/14偏移计算-phaseCorrelate-RftGeneric1:0.4595
差分筛选分块14/14偏移计算-phaseCorrelate-RftGeneric2:0.3605
差分筛选分块14/14偏移计算-phaseCorrelate-互功率谱+反变换:0.5754
差分筛选分块14/14偏移计算-phaseCorrelate总:1.9449
```

## 定位过程

通过拆分日志确认：

- 区域求交耗时约 `0.01ms` 级。
- 当前图/模板图裁剪耗时约 `0.01ms` 级。
- 越界裁剪处理耗时约 `0.01ms` 级。
- 主要耗时集中在 HALCON FFT 相关算子：
  - `RftGeneric1`
  - `RftGeneric2`
  - `PhaseCorrelationFft + RftGeneric(from_freq)`

部署机上三段 FFT 相关耗时合计：

```text
5.1718 + 5.5047 + 4.7884 = 15.4649 ms
```

占 `phaseCorrelate总` 约 `93.5%`。

因此瓶颈不是差分筛选业务逻辑，也不是裁图、region 求交或结果回填，而是 HALCON 小图 FFT 在部署机上的执行策略。

## 原因

原代码中 `BaseHTool::BaseHTool` 设置了 HALCON 自动并行化：

```cpp
SetSystem("parallelize_operators", "true");
```

该设置会让 HALCON 对部分算子启用自动并行。对于大图、大算子、吞吐型任务可能有收益，但当前差分筛选场景是：

- 每个分块约 `100x100`。
- 每张图可能有多个分块。
- 每块都调用一次 `RftGeneric / PhaseCorrelationFft`。
- 业务关注单次低延迟，而不是大批量吞吐。

小图 FFT 的计算量很小，开启自动并行后可能引入额外开销：

- HALCON 内部线程调度。
- worker thread 唤醒。
- 多线程同步等待。
- P/E 核混合 CPU 上的调度不稳定。
- 跨核缓存同步开销。

在 12900K 这类 P-core/E-core 混合架构上，HALCON 内部线程如果被调度到 E-core，或主线程等待较慢 worker，可能导致 100x100 小图 FFT 从 `0.3ms ~ 0.6ms` 放大到 `5ms` 级。

因此该问题本质是：

```text
HALCON 自动并行化策略与小图、高频、低延迟的差分筛选场景不匹配。
```

## 解决方法

现场验证后，将 HALCON 自动并行化显式关闭：

```cpp
SetSystem("parallelize_operators", "false");
```

位置：

```cpp
BaseTool/basetool.cpp
BaseHTool::BaseHTool()
```

建议保留显式 `false`，不要依赖 HALCON 默认值，避免不同机器、不同 HALCON 运行时环境表现不一致。

## 对结果的影响

`parallelize_operators` 只影响 HALCON 算子的自动并行调度策略，不改变算子语义。

现场验证结论：

- 设置为 `false` 后结果不变。
- 部署机差分筛选中 `RftGeneric / PhaseCorrelationFft` 耗时明显下降。
- 实时性更稳定。

## 后续建议

1. 对小图、高频、低延迟路径，避免默认开启 HALCON 自动并行化。
2. 保留当前拆分日志一段时间，用于确认不同机台是否仍有异常耗时。
3. 如果后续仍需进一步优化，可考虑将 100x100 小图相位校正改为 OpenCV `cv::phaseCorrelate`，减少 HALCON 对象和 FFT 调度开销。
4. 对大图或离线批处理路径，不应直接套用本结论，需要单独 profiling。
