# pi 图像阅读工具（GLM-4V）配置说明

- 创建日期：2026-08-15
- 工具类型：pi extension（非标准 MCP，见下文说明）
- 状态：已部署并测试通过（2026-08-15，字符测试图验证）

---

## 一、工具概述（What / Why）

**功能**：在 pi 中输入本地图像路径，通过智谱视觉语言模型 GLM-4V 理解图像内容，返回认知描述文字（主体、场景、字符/文字、明显异常等）。

**为什么不是标准 MCP**：pi 官方不支持 MCP 协议（无 MCP client），其原生等价方案是 extension + `registerTool()` 注册自定义工具供 LLM 调用。本工具按 pi extension 实现，效果等同。

**能力边界（重要）**：
- ✅ 适用：图像内容描述、印刷字符/文字提取、主体/场景/状态识别、明显异常辅助判断
- ❌ 不适用：产线细小瑕疵检测（污点/蚊虫/黑胶布/微小破口等）——精度远不如专用 OpenCV/HALCON 算法，不可替代瑕疵检测

## 二、文件组成与位置

```
C:\Users\<用户名>\.pi\agent\extensions\image-analyzer\
├── index.ts      extension 主体（零外部依赖，无需 npm install）
└── apikey.txt    智谱 API key（纯文本，一行）
```

- pi 启动时自动发现并加载；修改代码或 key 后在 pi 中执行 `/reload` 热重载，无需重启 pi
- 仅对当前 Windows 用户全局生效（所有项目可用）

## 三、配置步骤

1. **获取 API key**：https://open.bigmodel.cn 注册 → 控制台获取 API Key
2. **写入 key 文件**：把 key 粘贴到 `apikey.txt`（一行纯文本）
3. **重载**：pi 中执行 `/reload`
4. **验证**：对 pi 说"分析 G:\xxx.bmp，描述内容"，观察是否调用 `analyze_image` 工具并返回描述

**可选：环境变量方式（优先级高于 key 文件）**

| 环境变量 | 作用 | 默认值 |
|----------|------|--------|
| `GLM_API_KEY`（或 `ZHIPUAI_API_KEY` / `ZHIPU_API_KEY`） | API key | 无（回退读 apikey.txt） |
| `GLM_MODEL` | 默认模型 | `glm-4v-flash` |
| `GLM_BASE_URL` | 接口地址（换厂商用） | 智谱 OpenAI 兼容端点 |

> 注意：环境变量在 pi 进程启动时继承，修改后需重启 pi；key 文件方式只需 `/reload`，日常推荐后者。

## 四、使用方法

直接用自然语言，LLM 会自动调用工具：

```
分析 G:\test\sample.bmp，描述里面的内容
用 analyze_image 看看 D:\test\defect.png 有没有明显异常，重点关注印刷字符
```

**工具参数**（一般由 LLM 自动填，也可在对话中口头指定）：

| 参数 | 必填 | 说明 |
|------|------|------|
| `imagePath` | 是 | 本地图像路径（支持 jpg/png/bmp/gif/webp；BMP 自动转 PNG） |
| `question` | 否 | 关注点指令，如"这张图有哪些明显缺陷"；省略则整体描述 |
| `model` | 否 | 默认 `glm-4v-flash`（免费）；`glm-4v` / `glm-4v-plus` 更强但收费 |
| `maxTokens` | 否 | 返回上限，默认 1024 |

## 五、内部处理流程

```
LLM 调用 analyze_image
  → 读取图像文件（路径相对 pi 工作目录解析，自动去开头 @）
  → BMP 自动解码转 PNG（纯 TS，支持非压缩 8/24/32 位；云端 VLM 不支持 BMP）
  → base64 编码（智谱原生格式优先，400 时自动回退 OpenAI data URL 格式）
  → POST 智谱 OpenAI 兼容接口 /api/paas/v4/chat/completions
  → 返回认知描述文字给 LLM
```

## 六、常见问题排查（实际踩坑记录）

| 现象 | 原因 | 解决 |
|------|------|------|
| `HTTP 429 / code 1113 余额不足` | 账户无该模型额度（glm-4v 收费） | 用免费模型 `glm-4v-flash`（已设为默认），或充值 |
| `HTTP 400 / code 1210 参数有误` | BMP 格式不被 GLM-4V 接受 | 已内置 BMP→PNG 自动转换；若仍报错检查 BMP 是否为压缩格式（如 RLE） |
| `未配置智谱 API key` | apikey.txt 缺失且无环境变量 | 写入 key 文件后 `/reload` |
| `HTTP 401` | key 无效 | 核对 key，必要时去控制台轮换 |
| 大图失败 | 超过云端大小/分辨率限制 | 缩小图像后重试（代码对 >10MB 有提示） |

## 附录 A：extension 完整源码（index.ts）

> 将以下内容完整保存为 `%USERPROFILE%\.pi\agent\extensions\image-analyzer\index.ts`（UTF-8 编码）。
> 零外部依赖，无需 npm install。与本机运行版本一致。

```typescript
/**
 * pi extension: VLM 图像分析工具（智谱 GLM-4V）
 * 创建时间: 2026-08-15
 * 功能:   注册 analyze_image 工具，读取本地图像，通过智谱 GLM-4V
 *         （OpenAI 兼容接口）理解图像内容，返回认知描述文字。
 *         BMP 图像自动转 PNG 后上传（纯 TS 实现，支持非压缩 8/24/32 位）。
 * 目的:   为 pi 提供独立的"视觉语言模型图像理解"能力，可用专门 VLM
 *         与自定义指令做图像内容分析，行为统一、可复用。
 *
 * 配置（二选一，环境变量优先）:
 *   1. 环境变量:  GLM_API_KEY（或 ZHIPUAI_API_KEY / ZHIPU_API_KEY）
 *   2. key 文件:  ~/.pi/agent/extensions/image-analyzer/apikey.txt
 *                （内容为纯 key 文本；改文件后 /reload 即生效，无需重启 pi）
 * 其他可选环境变量:
 *   GLM_MODEL      默认模型名（可选，默认 glm-4v-flash）
 *   GLM_BASE_URL   接口地址（可选，默认智谱 OpenAI 兼容端点，换厂商时修改）
 */

import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";
import { Type } from "typebox";
import { readFile } from "node:fs/promises";
import { resolve, extname, basename } from "node:path";
import { homedir } from "node:os";
import { deflateSync } from "node:zlib";
import { Buffer } from "node:buffer";

// ---- 智谱 GLM-4V OpenAI 兼容接口默认配置 ----
const DEFAULT_BASE_URL = "https://open.bigmodel.cn/api/paas/v4/chat/completions";
const DEFAULT_MODEL = "glm-4v-flash"; // 免费模型；充值后可改 glm-4v / glm-4v-plus 获得更强识别力
const DEFAULT_QUESTION =
  "请详细描述这张图像的内容，包括主体、场景、状态以及任何值得注意的细节。";
const DEFAULT_MAX_TOKENS = 1024;
const SIZE_WARN_BYTES = 10 * 1024 * 1024; // 10MB 软提示阈值

// 图像扩展名 -> MIME
const EXT_TO_MEDIA: Record<string, string> = {
  ".jpg": "image/jpeg",
  ".jpeg": "image/jpeg",
  ".png": "image/png",
  ".gif": "image/gif",
  ".webp": "image/webp",
  ".bmp": "image/bmp",
};

// ---- BMP -> PNG 转换（纯 TS，零依赖。云端 VLM 通常不支持 BMP，需转 PNG）----

interface DecodedBmp {
  width: number;
  height: number;
  pixels: Buffer; // RGB，每像素 3 字节，自上而下
}

/** 解码非压缩 BMP（8 位调色板 / 24 位 / 32 位，BI_RGB） */
function decodeBmp(buf: Buffer): DecodedBmp {
  if (buf.length < 54 || buf[0] !== 0x42 || buf[1] !== 0x4d) {
    throw new Error("不是有效的 BMP 文件");
  }
  const dataOffset = buf.readUInt32LE(10);
  const dibSize = buf.readUInt32LE(14);
  if (dibSize < 40) {
    throw new Error(`不支持的 BMP 头 (DIB size=${dibSize})，仅支持 BITMAPINFOHEADER`);
  }
  const width = buf.readInt32LE(18);
  const rawHeight = buf.readInt32LE(22);
  const height = Math.abs(rawHeight);
  const bpp = buf.readUInt16LE(28);
  const compression = buf.readUInt32LE(30);
  if (compression !== 0) {
    throw new Error(`不支持的 BMP 压缩方式 (${compression})，仅支持非压缩 BI_RGB`);
  }
  if (bpp !== 8 && bpp !== 24 && bpp !== 32) {
    throw new Error(`不支持的 BMP 位深: ${bpp}（仅支持 8/24/32 位）`);
  }

  const srcStride = ((width * bpp + 31) >> 5) << 2; // BMP 行 4 字节对齐
  const dst = Buffer.alloc(width * height * 3);
  const bottomUp = rawHeight > 0; // 正高度 = 自下而上存储

  if (bpp === 8) {
    // 8 位调色板：色板在 DIB 头之后，每项 BGRA
    let nColorsUsed = buf.readUInt32LE(46);
    if (nColorsUsed === 0) nColorsUsed = 256;
    const palOff = 14 + dibSize;
    for (let y = 0; y < height; y++) {
      const srcY = bottomUp ? height - 1 - y : y;
      const src = dataOffset + srcY * srcStride;
      let d = y * width * 3;
      for (let x = 0; x < width; x++) {
        const p = palOff + buf[src + x] * 4;
        dst[d++] = buf[p + 2]; // R
        dst[d++] = buf[p + 1]; // G
        dst[d++] = buf[p]; // B
      }
    }
  } else {
    // 24/32 位：像素序 BGR(A)
    const nPxBytes = bpp >> 3;
    for (let y = 0; y < height; y++) {
      const srcY = bottomUp ? height - 1 - y : y;
      let src = dataOffset + srcY * srcStride;
      let d = y * width * 3;
      for (let x = 0; x < width; x++) {
        dst[d++] = buf[src + 2]; // R
        dst[d++] = buf[src + 1]; // G
        dst[d++] = buf[src]; // B
        src += nPxBytes;
      }
    }
  }
  return { width, height, pixels: dst };
}

/** PNG CRC32（IEEE 802.3，查表法） */
let CRC_TABLE: Int32Array | null = null;
function crc32(buf: Buffer): number {
  if (!CRC_TABLE) {
    const t = new Int32Array(256);
    for (let n = 0; n < 256; n++) {
      let c = n;
      for (let k = 0; k < 8; k++) c = c & 1 ? 0xedb88320 ^ (c >>> 1) : c >>> 1;
      t[n] = c;
    }
    CRC_TABLE = t;
  }
  let c = 0xffffffff;
  for (let i = 0; i < buf.length; i++) {
    c = CRC_TABLE[(c ^ buf[i]) & 0xff] ^ (c >>> 8);
  }
  return (c ^ 0xffffffff) >>> 0;
}

function pngChunk(type: string, data: Buffer): Buffer {
  const out = Buffer.alloc(12 + data.length);
  out.writeUInt32BE(data.length, 0);
  out.write(type, 4, "ascii");
  data.copy(out, 8);
  out.writeUInt32BE(crc32(Buffer.concat([Buffer.from(type, "ascii"), data])), 8 + data.length);
  return out;
}

/** 编码 8 位 RGB PNG（zlib 内置压缩，工业图像典型几百万像素约百 ms 级） */
function encodePng(img: DecodedBmp): Buffer {
  const { width, height, pixels } = img;
  const nRowBytes = width * 3 + 1; // 每行前加 1 字节滤波类型（0=None）
  const raw = Buffer.alloc(nRowBytes * height);
  for (let y = 0; y < height; y++) {
    raw[y * nRowBytes] = 0;
    pixels.copy(raw, y * nRowBytes + 1, y * width * 3, (y + 1) * width * 3);
  }
  const idat = deflateSync(raw, { level: 6 });
  const ihdr = Buffer.alloc(13);
  ihdr.writeUInt32BE(width, 0);
  ihdr.writeUInt32BE(height, 4);
  ihdr[8] = 8; // 位深
  ihdr[9] = 2; // 颜色类型 RGB
  return Buffer.concat([
    Buffer.from([0x89, 0x50, 0x4e, 0x47, 0x0d, 0x0a, 0x1a, 0x0a]),
    pngChunk("IHDR", ihdr),
    pngChunk("IDAT", idat),
    pngChunk("IEND", Buffer.alloc(0)),
  ]);
}

// key 文件位置（与 extension 同目录，免环境变量/免重启，改文件后 /reload 即可）
const APIKEY_FILE = resolve(
  homedir(), ".pi", "agent", "extensions", "image-analyzer", "apikey.txt"
);

/** 读取智谱 API key：优先环境变量，其次本地 apikey.txt */
async function readApiKey(): Promise<string> {
  const fromEnv =
    process.env.GLM_API_KEY ??
    process.env.ZHIPUAI_API_KEY ??
    process.env.ZHIPU_API_KEY;
  if (fromEnv && fromEnv.trim()) return fromEnv.trim();

  try {
    const content = await readFile(APIKEY_FILE, "utf8");
    const key = content.trim();
    if (key) return key;
  } catch {
    /* key 文件不存在则走报错分支 */
  }

  throw new Error(
    "未配置智谱 API key。请设置环境变量 GLM_API_KEY，或把 key 写入: " + APIKEY_FILE
  );
}

export default function (pi: ExtensionAPI) {
  pi.registerTool({
    name: "analyze_image",
    label: "Analyze Image (GLM-4V)",
    description: [
      "分析本地图像文件内容：通过视觉语言模型智谱 GLM-4V 理解图像，返回认知描述。",
      "适用：描述图像内容、识别主体/场景/状态、辅助判断明显异常。",
      "局限：对细小瑕疵（污点/蚊虫/微小破口等）的检测精度不如专用视觉算法。",
    ].join(" "),
    promptSnippet: "用 GLM-4V 视觉模型理解本地图像内容，输入图像路径",
    promptGuidelines: [
      "Use analyze_image when the user wants to understand or describe the content of a local image file. Pass imagePath (absolute or relative to cwd) and an optional question for what to focus on.",
    ],
    parameters: Type.Object({
      imagePath: Type.String({
        description: "本地图像文件路径（绝对路径，或相对当前工作目录；开头 @ 会自动去除）",
      }),
      question: Type.Optional(
        Type.String({
          description:
            "想让模型关注的问题/指令，如「这张图有哪些明显缺陷」「描述产品外观状态」。省略则做整体描述。",
        })
      ),
      model: Type.Optional(
        Type.String({
          description: "GLM-4V 系列模型名，默认 glm-4v-flash（免费）。可选 glm-4v / glm-4v-plus。",
        })
      ),
      maxTokens: Type.Optional(
        Type.Number({ description: "返回最大 token 数，默认 1024" })
      ),
    }),

    async execute(_toolCallId, params, signal, onUpdate, ctx) {
      // 1. 解析路径（strip 开头 @，相对 cwd 解析，与内置工具一致）
      let p = (params.imagePath ?? "").trim();
      if (p.startsWith("@")) p = p.slice(1);
      const absPath = resolve(ctx.cwd, p);

      const question = (params.question ?? "").trim() || DEFAULT_QUESTION;
      const model = params.model ?? process.env.GLM_MODEL ?? DEFAULT_MODEL;
      const maxTokens = params.maxTokens ?? DEFAULT_MAX_TOKENS;
      const baseUrl = process.env.GLM_BASE_URL ?? DEFAULT_BASE_URL;

      // 2. 读取图像 -> base64 data URL
      let buf: Buffer;
      try {
        buf = await readFile(absPath);
      } catch (e: any) {
        throw new Error(`无法读取图像文件: ${absPath} (${e?.message ?? e})`);
      }
      if (buf.length === 0) {
        throw new Error(`图像文件为空: ${absPath}`);
      }
      if (buf.length > SIZE_WARN_BYTES) {
        onUpdate?.({
          content: [
            {
              type: "text",
              text: `提示: 图像较大 (${(buf.length / 1024 / 1024).toFixed(1)}MB)，GLM-4V 可能对单图大小/分辨率有限制，如失败请缩小或压缩后再试。`,
            },
          ],
        });
      }

      const ext = extname(absPath).toLowerCase();
      let sendBuf = buf;
      let mediaType = EXT_TO_MEDIA[ext] ?? "image/jpeg";
      // BMP 需转 PNG（云端 VLM 通常不支持 BMP）
      if (ext === ".bmp") {
        onUpdate?.({ content: [{ type: "text", text: "检测到 BMP，转换为 PNG ..." }] });
        try {
          sendBuf = encodePng(decodeBmp(buf));
          mediaType = "image/png";
        } catch (e: any) {
          throw new Error(`BMP 转 PNG 失败: ${e?.message ?? e}`);
        }
      }
      const base64 = sendBuf.toString("base64");
      // 图像传入格式（依次尝试）:
      //   1. 智谱原生: url 直接填 base64 字符串（不带 data: 前缀）
      //   2. OpenAI 风格: data URL（兼容其他厂商接口）
      const imageRefs = [base64, `data:${mediaType};base64,${base64}`];

      // 3. 调用智谱 GLM-4V（OpenAI 兼容 /v1/chat/completions）
      const apiKey = await readApiKey();
      onUpdate?.({
        content: [
          { type: "text", text: `调用 GLM-4V (${model}) 分析图像: ${basename(absPath)} ...` },
        ],
      });

      // 依次尝试图像格式，参数错误(400)时自动换下一种
      let data: any = null;
      let lastErr: Error | null = null;
      for (let i = 0; i < imageRefs.length; i++) {
        let resp: Response;
        try {
          resp = await fetch(baseUrl, {
            method: "POST",
            headers: {
              "Content-Type": "application/json",
              Authorization: `Bearer ${apiKey}`,
            },
            body: JSON.stringify({
              model,
              messages: [
                {
                  role: "user",
                  content: [
                    { type: "text", text: question },
                    { type: "image_url", image_url: { url: imageRefs[i] } },
                  ],
                },
              ],
              max_tokens: maxTokens,
            }),
            signal,
          });
        } catch (e: any) {
          if (signal?.aborted) throw new Error("已取消");
          throw new Error(`GLM-4V API 网络请求失败: ${e?.message ?? e}`);
        }

        if (resp.ok) {
          data = await resp.json();
          break;
        }

        const errText = await resp.text().catch(() => "");
        lastErr = new Error(
          `GLM-4V API 请求失败: HTTP ${resp.status} ${resp.statusText}\n${errText}`
        );
        // 仅参数错误且还有备用格式时重试；其他错误（如 401/429）直接抛出
        if (resp.status !== 400 || i === imageRefs.length - 1) break;
        onUpdate?.({
          content: [{ type: "text", text: `图像格式 ${i + 1} 不被接受，尝试备用格式...` }],
        });
      }
      if (!data) throw lastErr ?? new Error("GLM-4V API 未知错误");

      // content 可能是字符串或数组，统一提取文本
      const raw: unknown = data?.choices?.[0]?.message?.content;
      let text: string;
      if (typeof raw === "string") {
        text = raw;
      } else if (Array.isArray(raw)) {
        text = raw
          .map((c: any) => (typeof c === "string" ? c : c?.text ?? ""))
          .join("");
      } else {
        text = raw == null ? "(模型未返回内容)" : JSON.stringify(raw);
      }

      return {
        content: [{ type: "text", text }],
        details: {
          model,
          imagePath: absPath,
          question,
          usage: data?.usage,
        },
      };
    },
  });
}
```
